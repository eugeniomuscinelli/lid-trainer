LID Table Trainer

Latency-insensitive RTL traces, HW3-style: data(void, stop) per channel, one-stop-to-stall backpressure. Fill the table, check it, then watch it animate.

1. Describe the system and the givens

Inputs: value per cycle, v suffix = void token (e.g. 2v), - = unknown value. Stops: 0/1 per cycle.

Spec format

cycles 15            # timestamps n = 1..15
queue 2              # input-queue capacity (number or inf)

shell S              # a shell encapsulating one core
  in x               # primary input channel
  in p <- A.q rs 1   # channel from register q of shell A,
                     #   pipelined with 1 relay station
  reg a = x + y init 2   # registered output a(n+1) = x(n)+y(n)
  reg m = a * z init -   # init = value at n = 1

output m = S.m       # primary output, read from S.m

x: 3 2 2v 1 4 5      # what the environment sends on x
stop m: 0 0 0 0 1 0  # stopIn on m from the environment

Expressions can use + - * / %, comparisons, && || ! and c ? a : b. Each reg is a flip-flop: its value at n+1 is the expression evaluated on the values at n (inputs and other registers of the same shell).

Protocol conventions used by the checker

These follow the shell and relay-station designs of Lecture 12 and the traces of HW3 (Problem 3). If your course uses a variant, tell Claude and the rules can be adjusted.

Shell control logic (Lecture 12 notation)

For a shell with input channels I and output channels O; emptyi and fulli are the state of queue i at the start of the cycle, x⁺ is the value registered for the next cycle.

fire        = ∧i∈I ( ¬voidIni ∨ ¬emptyi )  ∧  ¬ ∨j∈O ( stopInj ∧ ¬voidOutj )

voidOutj⁺  = 0        if stopInj ∧ ¬voidOutj        (token repeated for receiver j)
            = ¬fire    otherwise

stopOuti    = fulli

enqi       = ¬voidIni ∧ ( ¬fire ∨ ¬emptyi ) ∧ ¬fulli
deqi       = ¬emptyi ∧ fire
bypassi    = emptyi                          (a token arriving into an empty queue while firing is used directly)

registers⁺ = core( popped / bypassed tokens, registers )   if fire;  unchanged otherwise

The checker computes every cell of the table from these equations; the prose below is the same rules in words.

  • Timing. Every register, every void bit and every stop bit is clocked: the values in row n are the state at timestamp n. A register's value at n+1 is computed from the values at n. Row 1 holds the initial state (registers at their init value, queues empty, relay stations holding a void token).
  • Input queues. Each shell input has a bypassable queue. A valid token arriving at n when stop=0 is accepted; it is consumed immediately (bypass) if the queue is empty and the shell fires at n, otherwise it is stored behind the tokens already there. Void tokens are never stored.
  • Firing. A shell fires at n iff every input channel has a token available (queue head, or the token arriving at n) and none of its valid output tokens is being stopped at n. When it fires it pops one token from every input queue, and the core computes the registers for n+1 (void = 0 on every output).
  • Stalling. If some input has no token, the shell stalls: registers hold, and at n+1 each output repeats its token marked void = 1 (the receiver already sampled it). If instead a valid output token is stopped at n, the shell also stalls, but that output repeats the token at n+1 with void = 0, since the receiver did not sample it.
  • Stop (one-stop-to-stall backpressure). The stop bit a shell raises on an input channel at n is 1 iff the tokens left in that queue from the previous cycles already fill it. The token arriving at n is then rejected, and the sender must repeat it at n+1. The environment repeats a rejected token at n+1; if the environment was going to send a void bubble at n+1, the bubble is absorbed by the repeat; otherwise the rest of the stream shifts by one cycle.
  • Queue column. Shows the tokens stored in the queue at n, before the pop of cycle n: the leftover tokens from earlier cycles plus the token arriving at n if it was accepted and not bypassed. Empty queue = leave blank.
  • Relay station (capacity 2, latency 1, init void). In the processing state it relays the incoming token (valid or void) to its output at n+1. If its valid output token is stopped at n: a void incoming token is discarded and the output is repeated; a valid incoming token is parked in the auxiliary flip-flop, the output is repeated, and stopOut goes to 1 at n+1 (stalling state). In the stalling state the incoming token is rejected; when stopIn drops, the parked token moves to the output at n+1 and stopOut drops.
  • Unknown values. - is a valid token with unknown value; any computation involving it gives -.
  • Answers. Blank void/stop cells count as 0; a blank queue cell means empty; a blank data cell counts as unanswered. Queue contents are written head first, e.g. 2,7. A backslash on the head, \2,7, means “2 was at the head at this cycle and the shell fired, so it was consumed” (the solution uses this notation; omitting the backslash is also accepted, marking a head as consumed when the shell stalls is not). A token that bypasses the queue is not stored: leave the cell blank or write \5. The data of a void token is don't-care: the solution shows the repeated value (as in HW3) but - is accepted too (as in the slides).
